# Phase 03: Authentication & Role-Based Access Control (RBAC) - Context

**Gathered:** 2026-11-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 3 delivers secure user authentication and role-based access control (RBAC) for the Automated Secure Examination System:
1. Super Admin account bootstrapping via a dedicated CLI script.
2. Secure credential authentication with JWT tokens stored in `httpOnly` cookies (with `Authorization: Bearer` fallback support for Postman API testing).
3. Role verification middleware (`verifyToken` and `authorizeRoles`) enforcing strict boundaries between `admin`, `faculty`, and `student`.
4. Admin user management endpoints allowing single registration of Faculty and Students, as well as a batch registration endpoint for Student cohorts.
5. Strict prevention of duplicate USNs (for students) and registered emails across all roles.

</domain>

<decisions>
## Implementation Decisions

### 1. Super Admin Seeding & Credential Strategy
- **D-01:** Admin creation will be managed via a standalone CLI script (`npm run seed:admin` calling `server/src/utils/seedAdmin.js`).
  - Reads `ADMIN_NAME`, `ADMIN_EMAIL`, and `ADMIN_PASSWORD` from `.env`.
  - Checks if an admin account already exists to ensure idempotency (will not overwrite existing Admin accounts).
  - Keeps production deployment clean and avoids accidental hardcoded credential commits.
  — **Reversibility:** reversible

### 2. JWT Session & Storage Architecture
- **D-02:** Hybrid token delivery: The server issues JWTs inside secure `httpOnly` cookies to protect against XSS attacks, while also supporting the `Authorization: Bearer <token>` header to facilitate automated Postman test runs.
  - Payload claims: `{ id: user._id, role: user.role, email: user.email, usn: user.usn }`.
  - Configurable expiration (default `24h` in `.env`).
  — **Reversibility:** costly — touches auth middleware and client Axios interceptors.

### 3. User Onboarding Flow (Admin Controlled)
- **D-03:** Admin endpoints support:
  - `POST /api/admin/users/faculty`: Creates faculty with name, email, initial password.
  - `POST /api/admin/users/student`: Creates student with mandatory USN, name, email, initial password.
  - `POST /api/admin/users/students/bulk`: Batch registration taking an array of student objects, returning processed counts, skipped duplicates, and detailed errors for invalid entries.
  — **Reversibility:** reversible

### 4. Route Guards & Security Responses
- **D-04:** Strict HTTP status separation:
  - `401 Unauthorized`: Returned when authentication token is missing, invalid, or expired (`{ success: false, message: 'Authentication required. No valid session found.' }`).
  - `403 Forbidden`: Returned when an authenticated user attempts to access an endpoint restricted to other roles (`{ success: false, message: 'Forbidden: Insufficient privileges.' }`).
  — **Reversibility:** reversible

</decisions>
